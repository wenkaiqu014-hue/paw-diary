沿用本机原测试目录、报告、已授权合成档案及登录状态。已有1.0验收包就继续用；包内原全量清单被本任务补充，不重跑已经通过的登录、日历、断网和完整备份。单项建议最多15分钟，无法取得真实证据时写清原因并继续，不反复要求用户重做。按下面顺序执行，需要用户配合的原生缩放、原图标打开和听读尽量集中一次，具体告诉用户该点哪里。

1. 原生200%修复复验。先在新网页确认最终 buildId/CSS，使用 Edge 菜单实际调到200%，复现原报告窄窗口宽度，截图记录实际窗口和页面宽度、原生缩放比例。重点检查顶部示例说明不再逐字竖排，登录/开始记录入口不被记录助手挡住，菜单、帮助、登录、宠物和记录表单文字可读，保存/取消可滚动到并用键盘操作。不用CSS zoom或设备模拟代替原生缩放。结束恢复原缩放。没有最终构件时先排查普通新标签是否拿到新版本，不清站点数据。

2. 原日常 App 图标重开。先核对并安全保存原App未保存输入；如有更新提示，按正常站内流程更新。关闭后请用户从原来的开始菜单/桌面图标重新打开，检查没有普通网页地址栏、进入最终1.0构件、既有记录和图片回读。保留该日常App及其资料；新装隔离App不能替代原图标测试。若原0.8→1.0过程此前没观察到，这次只能报告原App当前版本与重开回读，不能据此新增跨版本升级通过。可在App内再做一遍200%说明区检查。

3. Narrator 保存状态实际听读。在已授权的合成测试宠物上，新建一条明确标注测试的记录，用户用 Win+Ctrl+Enter 开启系统 Narrator 并用键盘操作保存。请用户确认实际听到的保存状态、是否重复或漏读、焦点和退出是否正常。保存期间太短时可记录真实网络限速方法后再观察；没有听到“保存中”则单列未验证，不能凭DOM或live region声称已朗读。成功反馈是否读出也独立记录；别重复发送登录邮件。仅在需要时请用户直接输入内测码/邮箱验证码，不读取、不写入报告。完成恢复用户原来的 Narrator 偏好。

4. 剩余更新组合，仅用仍存在的真实旧现场。先前 dirty-update、saving-update、照片跨升级还缺证据；如果原0.8页面或真实较旧1.0构件仍打开且能正常发现新构件，可补测，并记录起止buildId。未保存输入/合成图片存在、真实云保存期间，检查正常用户操作能否触发刷新以及输入是否保留。对真正保存请求限速可以，修改busy、版本metadata、service worker或直接调用隐藏函数不可以。若更新按钮被模态遮挡，记录正常UI阻止点击和草稿保留，但直接更新保护分支保持未验证。无真实旧现场就停止本项，保留未验证；不要降级生产、清缓存、重建旧profile或人为制造更新。1.0较旧构件的结果不能改写成0.8→1.0通过。照片测试区分选图/帮助/语言保稿、跨真实升级、保存刷新，分别写结论。

5. 精确清理。补测完成后，只对本轮及上轮有明确创建记录/ID的合成记录、宠物、类型和附件做正常界面清理，核对其它资料保留。不能确认所属的资源保留并说明；不要删除真实健康资料、清空回收站或清全部浏览器资料。先前隔离测试App已卸载，不重复卸载日常App。备份仅本机保留，报告记录清理范围与遗留原因。

6. 独立补测报告。在旧工具包目录运行：

`powershell.exe -NoProfile -File .\check-public.ps1 -ExpectedVersion 1.0.0 -OutFile .\public-followup.json`
