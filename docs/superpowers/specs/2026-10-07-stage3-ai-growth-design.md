# 阶段3：AI记录、成长回顾与首页布局设计

状态：2026-10-07用户已回答第一轮grill，六项均采用建议，追加“同行卡片尽量宽度一致”。本文将这些决定落成可审查设计；本轮产品代码、本地和真云主线已验收，v0.4.0已完成原URL复验及新tag/Release。用户要求本session完成阶段3，但实际结果须依验收记录。

## 目标与边界

完成“建档 → 第一笔记录 → 提醒 → 成长回顾”，新增一句话记录、只读记录助手，并修复成长首页。保留已有HTML/CSS/ESM、CloudBase、四个hash、原GitHub仓库/Pages地址和v0.3.0数据语义。界面与AI输出支持中文/英文，用户原文不自动翻译。

本阶段不引入语音、向量数据库、通用Agent框架、模型工具调用、一般健康咨询、真实社区发布或新登录方式。真实社区在阶段4；遮罩说明/版本新内容/PWA/最终真机验收在阶段5。按基本需求实现，测试集中于正常主线、确认保存、权限/费用边界和已有数据不回归。

## 已确认决定

1. 免登录用户可获得少量真实AI体验，登录额度更高；本地资料只在用户主动点击生成时提交必要内容。
2. 免费优先；开发AI验收预算不超过20元，上线AI预算不超过20元/月。它们是预算上限，不是报价，也不包括已开通CloudBase套餐。额外收费接入仍需给出具体方案，禁止集团账单或自动切收费模型。
3. 空档案首页提供明显的“开始记录”入口，点击后走三步；已有宠物只提示缺少步骤；新增宠物可选择引导，不强制打断。
4. 回顾默认最近7天（今天及前6天），支持最近30天和自定义日期；先展示真实数字，再给简短温暖日记。无记录不请求模型。
5. 助手支持页面内短对话，回答附来源；切宠物/空间/账号清空，刷新不保留聊天，仅回答网站使用和当前宠物记录。
6. 保留现有配色与卡片视觉，可调整网格/顺序；同行卡片尽量等宽，同列边缘、全宽区块和间距统一。

桌面采用一个两等列grid：


## 最小AI服务架构

新增独立`paw-ai`，沿用当前公开CloudBase `callFunction`网关，不新建HTTP服务，不启用匿名登录provider。函数运行时先沿Node18.15/256MB，部署超时40秒、模型请求25秒、前端等待35秒；这是一组待真实部署读回及smoke验证的配置。原`paw-api`保持3秒，已有认证和健康写库路径继续复用。

`paw-ai`只提供`ai.quota`、`ai.records.parse`、`ai.recaps.generate`、`ai.assistant.ask`。前三种生成/提问均不写健康档案、私有回顾或社区；只允许限额计数写入。无模型tools，不接受客户端指定模型、端点或系统提示。生成结果经结构校验后返回。

登录分支复用`resolvePrincipal`的可信平台UID及邮箱/OTP证明，再按owner读取服务端完整快照并过滤回收站。请求若带token但验证失败，拒绝，不回退访客。免登录分支仅处理用户明确提交的文字、候选宠物及当前本地可见记录，不读取任何私有云档案；来源标为“当前浏览器提供的记录”。示例仍明确标示，不将其称作用户真实经历。

API Key仅由服务端`process.env.TEXT_AI_API_KEY`读取；本机保存为`SILICONFLOW_API_KEY`，部署脚本从`os.environ`读取并仅注入paw-ai的TEXT_AI_API_KEY，不进入前端构建。供应商地址和模型由`TEXT_AI_BASE_URL`、`TEXT_AI_MODEL`配置并限制为最终核准组合。云管理仅用`TENCENTCLOUD_FUJI_*`；不硬编码/回显/提交秘密，不默认复用MiniMax语音Key。

供应商已由用户异步回答确定为硅基免费优先，用户准备实名账号和Key；魔搭仅比较备选，DeepSeek本轮不接入。Task2要求官方0价/免费说明、当前账号可用模型与少量真实smoke三者都满足才启用。默认不自动转收费供应商；没有可用Key时可以完成本地实现，但阶段3真实AI验收不能勾选。公开证据及未覆盖范围见[接入研究](../../research/2026-10-07-stage3-text-ai.md)。

## 限额与正常失败

初始免费配置：访客每日3次（访客ID与可信IP均限制），登录用户每日20次，单IP每日30次，全站每日100次、每月1000次模型尝试。按Asia/Shanghai划日/月，三项AI功能共用额度；`ai.quota`不消耗生成额度。UI显示有效剩余额度和重置说明，不承诺永久免费。

计数集中在直接读写deny的`ai_usage`集合，事务内预占所有适用计数后才发请求。随机访客ID仅辅助公平，IP来自可信`TCB_SOURCE_IP`；缺失可信IP时拒绝访客生成。全站额度兜底，内存计数不能作为费用保障。重复requestId不再调用模型；失败/超时不自动重试，用户主动重试算新尝试并有说明，避免已计费请求退款后突破上限。仅存哈希键、时间、次数与requestId/状态，不存提问或健康原文。

免费配置不构成收费模型20元/月的精确硬上限。若改收费模型，先按官方价格、最大输入/输出、月额度重新计算并降低配置，经具体确认后才能开启；优先使用供应商余额/消费限制，不声称应用计数可限制所有云端账单。

输入文字1–1000字；自然语言最多返回5条草稿；助手最多保留最近4轮，检索默认最近30天；模型最多输出1200token，序列化messages总量不超过24KiB。回顾/助手先计算完整范围统计，模型仅收最多20条相关记录（每条备注最多200字）及10条相关提醒，超出时提示片段范围，不冒充已读全部备注。不发送头像、照片、邮箱或账号UID给模型。

超时、限流、额度耗尽、空正文/非法结构均展示简明原因，保留原文或已有回顾；手动记录始终可用。不显示供应商原始错误、堆栈、推理字段或HTML。切宠物/空间/账号后迟到响应丢弃，绑定repo引用、generation、workspaceId、petId，不能只检查generation。

## 一句话记录与确认保存

“记一笔”提供“一句话记录 / 手动填写”，一个主入口。提交前说明必要资料会交给AI供应商；用户点击才请求。服务端按Asia/Shanghai确定today，模型整理绝对日期、类型、体重/单位、标题、备注和明确提到的下次日期；日期模糊、同名宠物归属模糊时保留空字段让用户补。斤转kg并显示原单位，不编造药物、剂量或诊断。

草稿形状`{draftId,petId,type,typeLabel?,occurredDate,value,unit,title,note,nextDate,missingFields,sourceText}`，允许待补字段为null。显示原句和归属，可编辑、取消、勾选；缺字段不能确认。草稿首版仅在当前页面内存，不建立云端ai_drafts集合；刷新前明确未确认草稿未保存。

确认调用同一仓储`saveRecordBatch(inputs,{baseRevision,operationId})`，本地/云均一次事务处理最多5条，复用现有`applyRecord`校验及关联提醒规则。单条确认也是一个元素的batch；重复操作不重复创建，批次失败不留半批。AI只产生草稿，仓储重新校验当前宠物、权限和字段。草稿取消不写库；保存成功后显示实际记录/提醒数量。

## 可恢复三步引导

步骤是`pet → record → reminder → done`。建档复用现有宠物表单；记录支持AI/手动；提醒可以设置或跳过。无需补全品种、头像或历史护理才能完成。已有宠物的提示按实际实体计算，新宠物是否走引导由用户选择。

进度保存到`profile.stage3.onboardingByPet[petId]`，内容仅step、关联recordIds、reminderId及updatedAt，不存聊天/未提交原句。无宠物时入口状态由空快照派生。已完成业务写入后再推进；恢复时核对可见实体，删除相关实体时重新提示缺少步骤，不重复建档。支持用户选择“以后再说”。

## 成长回顾与分享预览

完整范围内的可见记录/护理由代码计算：记录次数、体重差（四舍五入到0.01kg）、完成护理次数、范围终止日to之后7天（to+1～to+7）的已设置待办。单次体重没有差值；零记录不调用模型。模型仅写短日记，结构中引用的recordId/reminderId必须属于提供的来源。文案不把体重变化称作健康改善。

`Recap={id,petId,from,to,generatedAt,sourceHash,recordIds,reminderIds,facts,story,storySources,uiLocale}`。依据入口显示原始记录；修改/删除/补入范围内记录或相关提醒时用完整依据hash判定过时，而非仅看原ID。生成只产生预览，用户点击“保存回顾”才存私有档案；旧回顾在生成失败时保留。

保存位置为`profile.stage3.recaps`，走仓储`saveRecap(recap,{baseRevision,operationId})`，按真实可见宠物/依据校验，支持刷新/登录后读取。回顾元数据随现有V3完整备份，旧快照没有stage3字段仍能读取；不改变媒体/回收站/旧原文保留。

分享只提供可编辑预览及复制文字；默认不含体重、护理健康细节或原始记录。分享文案由独立不带健康数字的字段/安全模板生成，不用删除数字的正则假装去隐私。当前阶段不发布社区帖子，取消预览不写库。

## 只读浮动助手

入口可在四页使用，桌面侧面板、手机dialog；显示当前宠物及范围、欢迎语和三个快捷问题。帮助资料来自实际已发布功能，按词条/关键词匹配，不引入向量库。明确区分使用帮助、当前记录查询和暂不支持的医疗建议。

回答`{answer,sources:[{kind:'help'|'record'|'reminder',id,label}]}`；来源须属于本次检索上下文，点击可打开对应帮助或现有记录详情。默认最近30天，用户明确日期时限定范围；无记录直接说明并引导记一笔。连续追问最多携带最近4轮，每次重新读取当前范围；会话只在内存，切宠物/账号/空间立即清空，关闭面板可保留本页面会话，刷新清空。提问不能保存、编辑、删除或发布。

## 数据与接口约定

V3继续有效；仅新增可选`profile.stage3={onboardingByPet:{},recaps:[]}`。旧快照缺该字段时归一为空；服务端只接受明确的stage3写动作，不允许任意覆盖profile。

新增仓储接口：`saveRecordBatch(inputs,options):Promise<{records,reminders}>`、`saveOnboarding(progress,options):Promise<OnboardingProgress>`、`saveRecap(recap,options):Promise<Recap>`。云动作分别`records.saveBatch`、`stage3.onboarding.save`、`stage3.recap.save`，仍由`paw-api`短事务处理。本地批次的operationId回执存在envelope中，不进入用户记录；导入/迁移仍按现有记录ID与预览规则，不导入执行回执。

核心纯函数独立于UI：`validateRecordDraft`、`applyRecordBatch`、`advanceOnboarding`、`computeRecapFacts`、`recapSourceHash`、`prepareRecapShare`。前端AI请求层独立于健康仓储的自动重试逻辑。主agent统一拥有app.js、布局、部署与接口整合；独立worker可以拥有领域模块或AI后端，接口在计划中锁定，不并行改app.js。

## 验收与执行节奏

先完成首页骨架和真实模型/限额通路，再接草稿、引导、回顾、助手，最后集中验收原URL。账号/Key处理可以与本地模块并行；没有真实调用不能发AI版本。开发中逐任务RED→GREEN，结束一次独立审查并集中修复；视觉使用桌面/手机一批检查、必要修复后一批复验，不无限打磨。

退出要求：新手手动/AI两条路径均能完成；解析/取消不写、确认不重复；免登录真实调用且私有云仍拒绝；登录上下文不串宠物/账号；回顾事实/来源正确且能保存/标过时/安全预览；助手有来源且只读；1440/768/390双语布局等列/齐边/无横溢，个人照片墙可用；原246项回归及新增单测、真实模型和原URL检查通过。用户亲自体验单独记录，不代替其勾选。

v0.4.0已在真实模型、云配置和公开原URL验收通过后创建新tag/Release；旧tag不移动。详细任务与验证命令见同日实施计划。阶段3完成仍须给阶段4/5保留时间，原2026-10-08 20:00截止不变，估算不是工期保证。
